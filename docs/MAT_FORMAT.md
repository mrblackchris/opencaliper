# Acquisition MAT file format

OpenCaliper accepts the flat MATLAB variable layout generated by the acquisition script. The bundled [example.mat](../examples/example.mat) follows this convention with four synthetic channels. Run [example.py](../examples/example.py) to recreate it; the script replaces its selected output file. The example uses MATLAB-compatible HDF5 storage, just like the acquisition script. Classic MAT files written with `scipy.io.savemat` are also accepted.

## Channels and shared time base

Each channel has a numeric identifier, starting at 1. Identifiers may have gaps. OpenCaliper displays `Channel1`, `Channel2`, etc., in numeric order. The variables live at the top level of the file, rather than inside a MATLAB struct.

| Variable | Type | Meaning |
| --- | --- | --- |
| `points` | Positive integer scalar | Number of samples in every channel |
| `xinc` | Positive finite scalar | Time between stored samples, in seconds |
| `xorg` | Finite scalar | Horizontal origin in seconds; defaults to zero |
| `xref` | Finite scalar | Reference sample index; defaults to zero |
| `Channel1_t1` | Numeric vector of length `points` | Channel 1 amplitudes, despite the `_t1` suffix |
| `Channel1_unit` | Text | Physical unit, for example `VOLT` or `AMPere` |
| `Channel1_yinc` | Scalar | Vertical increment for raw integer scaling |
| `Channel1_offset` | Scalar | Physical offset for raw integer scaling |
| `date` | Text | Acquisition date; use `YYYY-MM-DD` |
| `time` | Text | Acquisition time; use `HH:MM:SS` |
| `samplerate` | Scalar | Optional acquisition metadata; not used to construct the time vector |
| `count` | Integer scalar | Optional acquisition count metadata |
| `format` | Text | Optional acquisition transfer format, e.g. `WORD`; does not determine the saved array dtype |

Repeat the four `Channel1_…` fields for each channel using its number. Samples must be a real numeric row or column vector; matrices with multiple rows and columns are rejected. All channels in this layout share the same time base and sample count. Use nonempty ASCII unit tokens without spaces. Missing units are displayed as `?`.

The time vector is **implicit**. Construct it in Python as:

```python
time = xorg + (np.arange(points) - xref) * xinc
```

For the bundled example, `points = 4096`, `xinc = 1e-6`, `xorg = -0.001`, and `xref = 0`. The first timestamp is −0.001 s and the last is 0.003095 s. There are `points - 1` intervals. Use `arange`, rather than `linspace(0, points*xinc, points)`, which changes the sample interval.

`xinc` is authoritative even if a device reports a different `samplerate` because of acquisition or transfer settings. An additional saved time vector is unnecessary and is not used by this importer.

## Physical values and raw ADC values

The usual acquisition files and bundled example store `ChannelN_t1` as **float32 physical values**. Floating-point samples are used directly: OpenCaliper does not apply `yinc` or `offset` again. For example, a stored value of `3.3` with unit `VOLT` means 3.3 V, regardless of the retained scaling metadata.

Unsigned `uint8` and `uint16` arrays are interpreted as raw ADC codes. These require a positive `ChannelN_yinc` and a finite `ChannelN_offset`:

```python
physical = (raw.astype(float) - 2**(bits - 1)) * yinc + offset
```

Here `bits` is 8 or 16 according to the array dtype. For new converters, writing floating-point physical values is usually simplest. Do not cast raw codes to float without first converting them to physical values. Other integer dtypes are not supported as raw ADC arrays.

Dates and times are metadata, independent of the relative time vector. Missing dates/times produce a warning and an epoch timestamp. Older acquisition files may contain separator-free strings; unambiguous values are accepted, but ambiguous timestamps are rejected. Use ISO-style strings in new files.

## Convert your own data

Read your source file, obtain its physical amplitudes and timestamps in seconds, then write these variables. This minimal example accepts one uniformly sampled channel:

```python
import numpy as np
from scipy.io import savemat

t = np.asarray(your_time_vector, dtype=float).reshape(-1)
y = np.asarray(your_physical_values, dtype=np.float32).reshape(-1)
if len(t) < 2 or len(t) != len(y) or not np.isfinite(t).all():
    raise ValueError('Expected matching sample and time vectors')
dt = t[1] - t[0]
if dt <= 0 or not np.allclose(np.diff(t), dt, rtol=1e-6, atol=abs(dt)*1e-8):
    raise ValueError('This acquisition layout requires uniform sampling')
savemat('measurement.mat', {
    'points': len(t), 'xinc': dt, 'xorg': t[0], 'xref': 0.0,
    'Channel1_t1': y, 'Channel1_unit': 'VOLT',
    'Channel1_yinc': 1.0, 'Channel1_offset': 0.0,
    'date': '2026-01-01', 'time': '12:00:00',
})
```

For MATLAB, the equivalent time reconstruction is:

```matlab
m = load('examples/example.mat');
t = double(m.xorg) + ((0:double(m.points)-1) - double(m.xref)) * double(m.xinc);
plot(t, m.Channel1_t1);
xlabel('Time (s)'); ylabel(m.Channel1_unit);
```

## OpenCaliper MAT exports

MAT export uses an additional interchange layout that preserves arbitrary channel names and independent time vectors. Each channel has `signal_0_name`, `signal_0_unit`, `signal_0_time` (seconds), and `signal_0_values`; subsequent channels use indices 1, 2, and so on. `recording_timestamp` stores an ISO timestamp. OpenCaliper can read these files back. This export layout differs from the shared-time-base acquisition convention demonstrated by `examples/example.py`.
